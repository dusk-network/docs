title: Upgrade a node
description: Update your Dusk node with the installer and confirm it is back in sync.

import { Tabs, TabItem } from '@astrojs/starlight/components';

Rerunning the [node installer](https://github.com/dusk-network/node-installer) upgrades a node in place. It re-pins the supported Rusk and Rusk Wallet versions, downloads and verifies the new binaries, and only then gracefully stops Rusk. Your consensus keys, user configuration, and chain state are preserved; the installer regenerates `rusk.toml`, `genesis.toml`, and the systemd unit.

:::caution[Keep the same network and role]
Rerun the installer with the **same network and feature flags** as your current node. Leaving out `--feature archive` on an archive node, for example, turns it back into a default node.
:::

## 1. Note the current state

So you can confirm the node recovers afterwards, record where it is now:

```sh
ruskquery info           # running Rusk version and chain
ruskquery block-height   # current height
```

## 2. Run the installer for your node

Pick the tab for your network, then the command for your node type.

<Tabs syncKey="network">
  <TabItem label="Mainnet">

  **Provisioner or full node**

  ```sh
  curl --proto '=https' --tlsv1.2 -sSfL \
    https://github.com/dusk-network/node-installer/releases/latest/download/node-installer.sh \
    | sudo bash
  ```

  **Archive node**

  ```sh
  curl --proto '=https' --tlsv1.2 -sSfL \
    https://github.com/dusk-network/node-installer/releases/latest/download/node-installer.sh \
    | sudo bash -s -- --feature archive
  ```

  </TabItem>
  <TabItem label="Testnet">

  **Provisioner or full node**

  ```sh
  curl --proto '=https' --tlsv1.2 -sSfL \
    https://github.com/dusk-network/node-installer/releases/latest/download/node-installer.sh \
    | sudo bash -s -- --network testnet
  ```

  **Archive node**

  ```sh
  curl --proto '=https' --tlsv1.2 -sSfL \
    https://github.com/dusk-network/node-installer/releases/latest/download/node-installer.sh \
    | sudo bash -s -- --network testnet --feature archive
  ```

  </TabItem>
</Tabs>

The installer leaves Rusk **stopped** after a successful run, so you can review the configuration before starting.

:::note[Custom `rusk.toml` settings]
The installer regenerates `rusk.toml`. If you had intentional changes there, reapply only those values to the new file before starting. Archive operators usually need to restore their `[http]` block (see the [archive node guide](/operator/archive-node/)).
:::

## 3. Start Rusk and confirm it worked

```sh
sudo systemctl start rusk
```

Give it a few seconds, then check the node with `ruskquery` rather than digging through logs:

```sh
ruskquery info           # new Rusk version and chain
ruskquery peers          # should be non-zero
ruskquery block-height   # run it a few times, about 10 seconds apart
```

**You're back up when `ruskquery peers` is non-zero and the block height keeps climbing.** `ruskquery info` should show the new Rusk version. After about 30 seconds, compare your height with the [network explorer](/operator/networks/). On an archive node, also run an archive GraphQL query before sending API traffic back to it.

## If Rusk doesn't start

`ruskquery` talks to a running node, so when Rusk is down it has nothing to answer. Read the service and its logs directly instead:

```sh
sudo systemctl status rusk --no-pager
sudo journalctl -u rusk --since "15 minutes ago" --no-pager
sudo tail -n 100 /var/log/rusk_recovery.log
```

A failure to start is often a wrong wallet password or no peers being found. Don't rerun the installer in a loop before you understand the first error. See [Troubleshooting](/operator/troubleshooting/), and [Roll back a node update](/operator/guides/rollback-node-update/) if a release needs reverting. If the node can't catch back up, use [manual resync](/operator/guides/manual-resync/).

## Testnet resets

Testnet can be reset independently of mainnet. After an announced reset, reinstall with `--network testnet`, then follow the [fast-sync](/operator/guides/fast-sync/) or reset steps from the announcement. Don't reset state just because a normal upgrade briefly lags the network.
